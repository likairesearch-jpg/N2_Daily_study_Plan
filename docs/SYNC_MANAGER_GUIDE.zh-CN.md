# 主目录管理器使用说明

唯一日常入口：`C:\LI KAI\AI\_Programing\N2_Daily\N2 Sync Manager.vbs`。
关闭旧窗口后重新双击。开发目录仍保留备份与草稿，但不再用于日常发布或控制正式每日任务。

## 四页分工

| 页面 | 唯一职责 |
|---|---|
| 学习计划 | 读取、新建、保存、另存为配置；删除实验配置；设为正式方案；N2 覆盖分析 |
| 课程草稿 | 选择正式/实验类型及具体文件；新建、生成/复制 Work 指令；仅校验；本地晋升；删除草稿；模板导入/导出 |
| 发布与同步 | 查看待发布变化；立即同步全部已批准课程；撤下实验；每日任务启停；刷新线上/本地发布状态 |
| 参考资料库 | 查看本地来源与 snapshot；显式手动联网更新 |

不再在多个页面重复生成 Context、校验或晋升。不再使用独立 Week 数字框定位草稿。“另存为”承担原“复制”的作用。

## 将满意的实验方案设为正式方案

1. 在学习计划页选择实验 Profile，点击读取。修改过参数时先保存。
2. 点击“设为正式方案”，核对与旧正式方案的差异。
3. 确认后，旧配置备份到 `.sync/official-profile-backups/`，正式默认保存在 `config/profiles/official-default.json`。
4. 以后新建正式草稿时绑定这份新方案。页面显示当前正式默认与生效范围。

已有草稿保留自己的快照，已发布课程不会被改写。此操作不把实验 Session 变为正式 Week，也不生成教学内容。配置包含的参数和扩展字段会继承；没有明确写入配置的教学风格不会被自动推断。

## 正式或实验课程准备

1. 进入课程草稿页，选择类型。正式草稿自动使用正式默认；实验草稿使用学习计划页当前已保存的实验配置。
2. 新建草稿后点击刷新列表，选中实际 JSON 文件。正式新建默认使用当前最新正式 Week 的下一周；已有同名草稿不会覆盖。
3. 实验可选择完成后总节数 1–7。点击“生成 Work 指令”，专用 Context 会按该草稿快照生成，再点击复制交给 Work。
4. Work 填写并保存同一文件后，先“仅校验”；通过后“晋升到本地待发布区”。
5. 晋升提示“本地晋升成功，尚未发布到网站”。晋升即批准进入每日/手动同步，未完成的草稿不会自动发布。

正式专用材料：`reports/formal-contexts/weekXX/`。实验专用材料：`reports/experiment-contexts/<id>/`。不覆盖共用 Context。

模板按类型分别保存：`config/formal-prompt-template.md`、`config/experiment-prompt-template.md`。在课程草稿页导出、编辑并导入对应类型模板；保留占位符。导入备份在 `.sync/template-backups/`。修改模板后重新生成指令，不会改变已保存的草稿快照。

## 发布与撤下

- “立即同步已批准课程”同步所有已晋升变化；不替未完成草稿晋升。
- 待发布列表区分本地未提交变化与未推送提交数。已推送不等于已部署；“刷新发布状态（联网）”读取线上 Pages 课程版本与本地状态。
- “撤下实验版本”先备份到 `.sync/withdrawn-experiments/`，再撤下并同步，也可能同步其他已批准变化。草稿、配置及学习进度保留。正式课程不能通过此按钮删除。
- 离线用户在成功联网更新前仍可能看到旧缓存。
- 每日同步仍为 Windows 本地时间 16:00。关闭窗口不停止任务；停止任务不撤回线上内容。
- 参考库不定时自动刷新，只有手动更新按钮访问上游。

开发入口发布与任务控制已禁用；不要交替在两个目录修改同一份计划。迁移时复制已有配置与草稿，没有覆盖正式 Week01–03，也没有自动把开发目录已晋升实验上线。
